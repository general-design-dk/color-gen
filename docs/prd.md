# PRD — 색칠요정 (색칠공부 제너레이터)

> 버전: v0.5 · 작성일: 2026-09-30 · 수정: 2026-10-04
> 용도: AI 커뮤니티 과제(PRD → 유저플로우 → 워크플로우 → 하네싱) + 실제 서비스 구현

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 색칠요정 |
| 한 줄 설명 | 키워드만 입력하면 아이용 **색칠공부 도안**을 AI로 만들어 주는 웹 서비스 |
| 형태 | 단일 페이지 반응형 웹 (모바일·태블릿·PC) |
| 성격 | **비상업적 개인 프로젝트** — 딸아이와 가족·지인이 쓰는 용도 |
| 핵심 가치 | 인터넷에 도안이 없는 캐릭터·소재도 **즉시, 바로 인쇄 가능한** 형태로 제공 |

## 2. 배경 및 문제 정의

- 아이가 "○○ 색칠공부 뽑아줘"라고 할 때, 유명 캐릭터는 도안이 많지만 비주류 캐릭터·동화 주인공(예: 엄지공주)은 도안이 거의 없다.
- 검색으로 찾은 도안도 선이 너무 복잡하거나, 워터마크·광고가 섞여 있어 인쇄에 부적합한 경우가 많다.
- → 생성형 AI로 **아동 친화적·인쇄 최적화**된 도안을 즉석에서 만들어 해결한다.

## 3. 목표 (MVP)
1. 키워드 입력 → 30초 이내 도안 1장 생성
2. 흑백 아웃라인 색칠공부 도안 생성 (단일 기능)
3. 생성 결과 다운로드(PNG) 및 A4 인쇄
4. 아동용과 무관하거나 부적절한 키워드 차단
5. 추천 키워드 칩으로 키워드를 빠르게 입력

## 4. 타깃 사용자

| 페르소나 | 설명 | 니즈 |
|---|---|---|
| 부모 (주 사용자) | 30~40대, 미취학~초등 저학년 자녀 | 아이가 원하는 걸 빠르게 뽑아주고 싶다. 조작이 간단해야 한다. |
| 아이 (보조 사용자) | 4~9세 | 원하는 캐릭터를 말하거나 직접 입력. 큰 버튼, 쉬운 화면. |
| 교사·보육교사 (확장) | 유치원·어린이집 | 수업 주제에 맞는 도안을 여러 장 인쇄 |

주요 사용 환경: 집에서 **스마트폰으로 생성 → 가정용 프린터로 인쇄**, 또는 PC에서 바로 인쇄.

## 5. 화면 구성

단일 페이지, 상태에 따라 영역이 바뀐다.

```
┌─────────────────────────────────┐
│  🧚 색칠요정  (로고 타이틀 헤더)    │
├─────────────────────────────────┤
│  ┌───────────────────────────┐  │
│  │                           │  │
│  │   캔버스 영역 (A4 세로 비율)  │  │
│  │   - 대기: 안내 일러스트      │  │
│  │   - 생성 중: 로딩 애니메이션  │  │
│  │   - 완료: 생성 이미지        │  │
│  └───────────────────────────┘  │
│  [ 키워드 입력창 (예: 엄지공주) ]    │
│  (공주)(공룡)(유니콘)… ← 추천 칩    │
│  [       ✨ 만들기 (메인버튼)     ]  │
│                                 │
│  (완료 후) [다운로드] [인쇄] [돌아가기] │
└─────────────────────────────────┘
```

| 요소 | 상세 |
|---|---|
| 헤더 | 로고 + 서비스명 |
| 캔버스 | A4 세로 비율(1:√2) 고정 영역. 대기/로딩/완료/에러 4가지 상태 |
| 키워드 입력창 | 최대 30자, 예시 placeholder |
| 추천 키워드 칩 | 입력창 아래 가로 스크롤 칩 6~8개 (예: 공주, 공룡, 유니콘, 소방차, 고양이, 인어공주). 칩 클릭 시 입력창에 채워짐(바로 생성하지 않음). 목록은 코드 상수로 관리 |
| 만들기 버튼 | 입력 없으면 비활성화. 생성 중 로딩 표시 + 중복 클릭 방지 |
| 결과 버튼 | 다운로드(PNG 저장), 인쇄(A4 인쇄 다이얼로그), 돌아가기(초기화) |
| 토스트 | 에러/차단 메시지 표시 (예: "색칠공부에 어울리는 키워드를 입력해 주세요 🙂") |

> **검토 메모**: 원안 화면 목록에 *키워드 입력창*이 빠져 있어 추가함.

## 6. 유저플로우

1. 키워드 입력 (또는 추천 키워드 칩 선택 → 입력창에 자동 입력)
2. [만들기] 클릭 → 서버에서 키워드 검증 → 통과 시 이미지 생성 (로딩 표시)
   - 검증 실패 → 토스트 메시지, 입력 상태 유지
   - 생성 실패/타임아웃 → 토스트 + 재시도 가능
3. 생성된 이미지 확인
4. [다운로드] → PNG 파일 저장 (`색칠요정_엄지공주_20260930.png`)
5. [인쇄] → A4 한 장에 꽉 차게 인쇄 (헤더·버튼 등 UI 숨김)
6. [돌아가기] → 입력값·결과 초기화, 대기 상태로 복귀

> **검토 메모**: 원안의 "출력버튼 → 출력"과 "인쇄버튼 → 인쇄"가 중복됨. **출력 = 다운로드**로 해석해 정리함.
> 상세 플로우는 [`userflow.md`](userflow.md) 참고.

## 7. 핵심 기능 요구사항

### F1. 키워드 검증 (Guardrail)
- 생성 전 LLM으로 키워드를 **분류**한다.
  - `allowed`: 캐릭터, 동물, 사물, 탈것, 자연, 음식, 동화 속 인물 등 아동용 도안에 적합
  - `rejected_irrelevant`: 풍경 사진·실사 요청 등 도안과 무관 (예: "뉴욕 사진")
  - `rejected_unsafe`: 폭력·선정·공포·혐오·실존 인물 등 아동 부적합
- 차단 시 토스트로 안내, 이미지 생성 API는 호출하지 않는다(비용 절감).
- 이미지 생성 API 자체의 안전 필터도 2차 방어선으로 사용.

### F2. 프롬프트 변환
- 같은 LLM 호출에서 한글 키워드를 **이미지 생성용 영문 프롬프트**로 변환한다. (예: 엄지공주 → "Thumbelina, a tiny princess sitting on a flower")
- 비상업적 개인 용도이므로 별도의 저작권 회피 재해석은 하지 않는다. 캐릭터 이름을 그대로 프롬프트에 사용한다.
- 단, 이미지 생성 API가 정책상 특정 캐릭터 생성을 거부하면 **캐릭터의 외형 특징을 묘사한 프롬프트로 한 번 재시도**한다.

### F3. 스타일 제약
| 항목 | 스타일 제약 |
|---|---|
| 색칠공부 도안 | 순수 흑백, 굵고 깨끗한 검정 외곽선, 채색·음영·그라데이션 없음, 흰 배경, 단순한 형태(유아가 칠하기 쉬운 넓은 면), 텍스트 없음, 세로 구도 |

- 스타일 제약은 **서버의 고정 시스템 프롬프트 템플릿**으로 관리(사용자가 조작 불가).

### F4. 결과 활용
- 다운로드: 원본 해상도 PNG
- 인쇄: `@media print` + `@page { size: A4 portrait; margin: 10mm }`로 이미지만 한 장에 맞춰 출력
- 모바일 인쇄: 브라우저 인쇄(`window.print()`) 사용, iOS/Android 공유 시트를 통한 프린터 연결 고려

### F5. 사용량 제한
- 공개 범위: Vercel 기본 도메인(`*.vercel.app`)으로 배포, 별도 도메인·홍보 없이 지인 공유 수준
- IP 기준 레이트 리밋 (예: 1분 3회, 하루 20회) — URL이 퍼질 경우 대비한 API 비용 보호
- 초과 시 토스트: "오늘은 요정이 쉬는 중이에요. 내일 다시 만나요!"

## 8. 기술 스펙

### 8.1 아키텍처

```
[브라우저 (Next.js 클라이언트)]
      │  POST /api/generate { keyword }
      ▼
[Next.js Route Handler (서버, Vercel)]
      ├─ ① 레이트 리밋 체크 (Upstash Redis)
      ├─ ② 입력 검증 (Zod: 길이·문자)
      ├─ ③ LLM: 키워드 분류 + 영문 프롬프트 변환 (JSON 응답)
      │       └─ 차단 → 400 + 사유 코드
      ├─ ④ 이미지 생성 API 호출 (색칠공부 스타일 템플릿 결합)
      └─ ⑤ 후처리: 흑백 이진화
      ▼
  { imageBase64 | imageUrl } 반환 → 캔버스 표시
```

- API 키는 **서버 환경변수에만** 보관, 클라이언트 노출 금지.
- MVP는 DB 없음(Stateless). 이미지는 응답으로만 전달하고 저장하지 않음.

| 영역 | 선택 | 이유 |

| 스타일링 | **Tailwind CSS** (+ 필요 시 shadcn/ui) | 반응형·빠른 UI 구현, 토스트 등 컴포넌트 재사용 |

| 상태관리 | React `useState`/`useReducer` | 단일 페이지·단순 상태(idle/loading/done/error)로 충분 |
| 입력 검증 | Zod | 클라이언트/서버 공통 스키마 |
| 키워드 분류·프롬프트 변환 LLM | **Claude Haiku 4.5** (`claude-haiku-4-5`) 또는 GPT 계열 경량 모델 | 빠르고 저렴, 구조화(JSON) 출력 |

| 분석(선택) | Vercel Analytics | 생성 수·차단율 확인 |
| 패키지 매니저 | pnpm | |
| 코드 품질 | ESLint + Prettier | |
| 테스트 | Vitest(프롬프트 빌더·검증 로직), Playwright(핵심 플로우 E2E) | 하네싱 과제에서 검증 루프로 활용 |

### 8.3 API 명세 (MVP)

`POST /api/generate`

```jsonc
// Request
{ "keyword": "엄지공주" }

// 200 OK
{ "image": "data:image/png;base64,...", "prompt": "(디버그용, prod에서는 생략)" }

// 400 — 차단
{ "error": "KEYWORD_REJECTED", "reason": "irrelevant" | "unsafe", "message": "색칠공부에 어울리는 키워드를 입력해 주세요" }

// 429 — 사용량 초과
{ "error": "RATE_LIMITED" }

// 502/504 — 생성 실패/타임아웃
{ "error": "GENERATION_FAILED" }
```

LLM 분류 응답 스키마 (서버 내부):
```jsonc
{
  "verdict": "allowed" | "rejected_irrelevant" | "rejected_unsafe",
  "subject_en": "Thumbelina, a tiny princess sitting on a flower petal",
  "fallback_en": "a tiny princess with long hair and a flower dress, sitting on a flower petal"
}
```

### 8.4 이미지 모델 선정 기준 (개발 초기 스파이크)
구현 과정에서 동일 키워드 10개로 후보 모델을 비교해 결정. `IMAGE_PROVIDER` 환경변수로 전환하며 테스트.

| 기준 | 측정 |
|---|---|
| 라인아트 준수 | 색칠공부에서 채색·음영 섞이는 비율 |
| 선 품질 | 선 굵기 균일, 닫힌 면(칠하기 쉬움) |
| 캐릭터 표현 | 캐릭터 이름만으로 알아볼 수 있게 그리는지, 정책상 거부하는지 |
| 속도 | p90 응답시간 ≤ 30초 |
| 비용 | 장당 비용 |

### 8.5 비기능 요구사항

| 항목 | 기준 |
|---|---|
| 반응형 | 모바일 우선 설계. 세로형 이미지 + 버튼 구조 기준으로 화면 크기에 맞춰 대응 (최소·최대 폭은 추후 확정) |
| 성능 | 초기 로드 LCP < 2.5s, 생성 응답 p90 < 30s, 서버 타임아웃 60s |
| 이미지 | 세로 비율(약 2:3 또는 A4 비율), 최소 1024px 이상, 300dpi A4 인쇄 시 깨지지 않을 수준 |
| 인쇄 | Chrome/Safari/Edge에서 A4 1페이지로 출력 |
| 접근성 | 큰 터치 영역(≥ 44px), 충분한 대비, 버튼 aria-label |
| 보안 | API 키 서버 보관, 입력 길이 제한, 프롬프트 인젝션 방어(사용자 입력은 데이터로만 취급, 시스템 프롬프트와 분리) |
| 개인정보 | 로그인·저장 없음. 키워드/IP 로그는 레이트 리밋 목적 외 보관하지 않음 |
| 아동 안전 | LLM 분류 + 이미지 API 안전 필터 이중 방어 |

## 9. 성공 지표

| 지표 | 목표 |
|---|---|
| 생성 성공률 (허용 키워드 기준) | ≥ 95% |

## 10. 리스크 및 대응

| 리스크 | 대응 |
|---|---|
| 색칠공부에 음영·회색 섞임 | 프롬프트 강화 + sharp 이진화 후처리 |
| 이미지 API가 유명 캐릭터 생성을 거부 | 외형 특징 묘사 프롬프트(`fallback_en`)로 재시도 |
| API 비용 폭증 | 레이트 리밋, 분류 단계에서 조기 차단, 장당 비용 모니터링 |
| 생성 지연(20~30초) | 재미있는 로딩 연출("요정이 그리는 중…"), 타임아웃 후 재시도 안내 |
| 모델 교체 필요 | `generateImage` 어댑터 인터페이스로 공급자 분리 |
